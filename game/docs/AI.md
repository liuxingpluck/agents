# 快速决策模型(System 1)说明

游戏里的 AI 对手分两种:**脚本 AI**(写死的规则,战役里的敌人和 Boss 用它)和**神经网络**(自己练出来的,在「单挑 AI」里上场)。
本文讲的是后者:一个专门为这个游戏定制、完全在玩家浏览器里训练和运行的小模型。

## 一句话概括

它每 0.1 秒看一眼游戏的内部数据,立刻给出「往哪走 + 按哪个键」——不思考、不规划,只凭直觉反应,所以叫 System 1(快思考)。

## 它看什么(输入)

直接读游戏数据,不看画面。一共 46 个数字(`src/ml/obs.ts`):

| 类别 | 内容 |
|---|---|
| 位置 | 与对手的横向距离、纵深差、双方离地高度 |
| 速度 | 双方的水平 / 垂直速度 |
| 朝向 | 自己是否面对着对手、对手是否面对着自己 |
| 资源 | 双方生命、能量 |
| 状态 | 双方各处于哪种状态(自由 / 空中 / 出招 / 受击 / 被打飞 / 倒地 / 闪避 / 被抓) |
| 出招 | 自己这招打到第几帧、是否已命中;对手处于前摇 / 判定 / 收招的哪一段、这招够得着多远 |
| 其他 | 是否无敌、连击数、对手还要硬直多久、离版边多远、有没有飞行道具正朝自己飞来 |

所有方向都以「自己 → 对手」为正,所以站左边还是右边对它来说是一回事。

## 它输出什么(动作)

网络有两个输出头,各选一个(`src/ml/policy.ts`):

- **移动**(7 选 1):不动 / 靠近 / 远离 / 上 / 下 / 靠近并上 / 靠近并下
- **按键**(15 选 1):不按 / 轻拳 / 重拳 / 轻脚 / 重脚 / 跳 / 闪避 / 抓投 / 4 个技能 / 3 个指令技

指令技(比如 ↓→ + 轻)由程序代它搓出来,网络只需要决定「放第几个指令技」。

## 模型有多大

三层的小网络:46 → 48 → 48 → 22,约 5,700 个参数,连同训练状态存下来不到 100 KB。
每 6 帧才算一次,单次计算量很小,游戏里感觉不到开销。

## 怎么练(`train.html`)

用的是**进化策略**,不需要反向传播:

1. 以当前参数为中心,随机生成几十个「稍微变一点」的版本
2. 让每个版本去打几局,打分(造成伤害 − 承受伤害 + 胜负 + 少量连击奖励)
3. 分数高的那些变化方向更可信,把参数往那边挪一点
4. 重复

陪练有四档(`src/ml/evaluate.ts`):脚本 AI、「连打新手」机器人、自己过去的版本(自博弈)、以及**联赛**——
本机其他角色已经练好的模型会用它们各自的角色上场。所以多练几个角色之后,后练的会被逼着应付不同的打法。
多个后台线程(Web Worker)同时空跑对战,每秒模拟几十万帧。模型自动存在浏览器本地,关掉页面下次接着练,也可以导出 / 导入 JSON 文件。

实测(4 核容器,3 个线程):90 秒练 200 代,对连打机器人的胜率从 0% 升到 100%。

## 怎么用

- **看它打**:训练页右侧实时播放「当前模型 vs 脚本 AI」
- **和它打**:游戏标题画面按 **V** 进入单挑;对手从你所选角色的下一位开始找,第一个存有模型的角色就是对手,都没练过则用脚本 AI 顶替

## 为什么目前只用 CPU,没用显卡

你最初的要求是「利用浏览器的 CPU 或 GPU」。现在用的是 CPU 多线程,原因是:

- 训练时间几乎全花在**跑游戏模拟**上(判定、状态机),这部分是普通的程序逻辑,显卡帮不上忙
- 网络本身太小,在 CPU 上算一次只要几微秒;搬到显卡上,数据来回传输的开销反而更大
- 所以对这个规模的模型,多开几个 CPU 线程比用显卡划算

如果以后把模型做大(比如几十万参数、成批推理),再接 WebGPU 才有意义。这一步还没做。

## 目前的局限(实话实说)

- **陪练不够强**:前两档是写死的规则;联赛要等你先练出几个角色才有对手。真人大概率仍能轻松赢它。
- **一个模型只会一个角色**:训练时选的哪个角色,模型就只会用哪个;对手角色也是训练时固定的那个。
- **只会 1 对 1**:战役里一对多的场面它没练过,所以战役里的敌人仍然用脚本 AI。
- **每局最多 15 秒**:超时算平局,所以「胜率」数字会偏低。
- **算法简单**:进化策略稳但慢,样本效率不如 PPO 之类的方法。

## 接下来可以做的

1. 联赛目前是「后练的打先练的」单向关系;可以改成所有角色轮流训练、互相追赶
2. 给战役的精英怪用上神经网络(需要先练一对多)
3. 换更高效的算法,并在模型变大后接 WebGPU
4. 难度分级:把不同代数的快照存成「简单 / 普通 / 困难」对手
